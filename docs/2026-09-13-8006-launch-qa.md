## 1. P0 阻断项

### P0-1 · 8006 mini test 点击即崩溃，题目容器被清空

**现象**
在 `/praxis-8006-teaching-reading` 点击「Start the mini test」后，`#mini-test` 容器 `innerHTML` 长度变为 **0**，页面出现一个空白框。无题目、无选项、无结果、无注册卡片。

**实测异常**
```
TypeError: Cannot read properties of undefined (reading 'subtest')
    at renderQuestion (https://learndiag.com/js/quiz-8006.js?v=1:154:34)
    at start         (https://learndiag.com/js/quiz-8006.js?v=1:143:5)
```
复现率 **100%**（无头 Chromium 与多次独立页面加载均一致），无随机性，**每位访客都会遇到**。

**根因**（`site/js/quiz-8006.js`，纯类型不匹配）

| 行 | 代码 | 问题 |
|---|---|---|
| L27 | `var order = []; // question ids in presentation order` | 注释声明是 **id 数组** |
| L63-67 | `byDomain()` 返回 `{域名: [题目对象…]}` | — |
| L69-73 | `buildOrder(){ order = order.concat(shuffle(g[d] \|\| [])) }` | **实际塞进 `order` 的是题目对象，不是 id** |
| L147 | `var q = BANK.filter(x => x.id === order[pos])[0]` | 用 **id 去比对对象**，永远匹配不到 → `q === undefined` |
| L148 | `root.innerHTML = ''` | 先清空容器 |
| L154 | `el('span', null, q.subtest)` | 读 `undefined.subtest` → 抛错，容器停在已清空的空白状态 |

实现与注释不一致；`buildOrder()` 与 `renderQuestion()` 对 `order` 的元素类型约定相反。

**影响面**（这是它成为唯一阻断项的原因）
- 8006 标杆页的**练习入口完全不可用**，页面对外宣称的「30-question mini test with explanations」是空承诺。
- 产品链路 6 项中，**F1–F5 全部挂在 mini test 上**（`quiz-8006.js` 是 8006 唯一带「邮箱验证 + 结果保存 + 恢复」的表面；练习页 `practice-8006.js` 的额度闸门只给 `/login` 链接，没有原地注册流程）。
- 连带失效的事件：`result_view`、`signup_prompt_view`（mini test 侧）、`signup_start`、`signup_success`、`study_plan_unlock`。

**线上/本地一致性**
- 线上 `quiz-8006.js` md5 `08ee2016f7d346502f166e7558f382ef`，工作区 md5 `654e6ba3a53b87c936befbb49a3b7245`。
- 两者差异**仅**为 D14 的 state 分桶改动（`state.tests["8006"]`），**不含渲染逻辑**——即该 bug 在工作区同样存在，不存在「本地已修、只是没部署」。

**建议修复方向（仅建议，未改动任何代码）**
把 `order` 的类型统一。二选一：
1. `buildOrder` 存 id：`order = order.concat(shuffle(g[d] || []).map(q => q.id))`；或
2. `renderQuestion` 直接用对象：`var q = order[pos]`。
另建议 `renderQuestion` 改为**先取到 `q` 再清空容器**，避免同类异常再次把容器留成空白。

## 2. P1 问题

### P1-1 · 移动端导航与正文错位 50px

390px 视口实测：

| 元素 | 计算内边距 | 内容左边界 |
|---|---|---|
| `header.nav`（`.nav.wrap`） | `28px 0px 24px 0px` | **0px** |
| `article.wrap` | `0px 50px 0px 50px` | **50px** |

- **根因**：样式表中 `.nav{...padding:28px 0 24px...}` 位于 `.wrap` 及其 `@media(max-width:760px){.wrap{padding:0 50px}}` **之后**，同优先级后者胜出，把导航的横向内边距覆盖为 0。
- 桌面端被 `.wrap{max-width:760px;margin:0 auto}` 掩盖（两者都从 340px 开始），**只在 ≤760px 暴露**：正文缩进 50px，导航贴屏幕边缘，wordmark 与页面主体左对齐线不一致。
- 证据截图：`shot-mobile-390-_praxis-8006-teaching-reading.png`

### P1-2 · 390px 下「Official Sources」表格溢出 43px 且无法横向滚动

页面第 4 个表格（`# / Source / Link / Last verified`）：

| 指标 | 值 |
|---|---|
| 表格宽度 | 383px |
| 右边界 | 433px |
| 视口宽度 | 390px |
| **溢出** | **43px** |

- 父容器 `overflow-x: visible`，而 `html,body{overflow-x:hidden}` → 溢出部分被**直接裁掉**，用户既看不到也**无法横向滚动**。手机上「Last verified / Link」列残缺。
- 第 3 个表格（7002 vs 8006 对比）实测宽 317px、右边界 367px，虽未超视口但已超出正文内容区（340px），同样被裁。
- 对比：`/praxis-8006-practice` 在 390px 下溢出元素数为 **0**，问题仅出在标杆页。

### P1-3 · Article 结构化数据的 `publisher` 是悬空引用

页面共 3 个 JSON-LD 块（Article / FAQPage / BreadcrumbList），语法与必填字段校验均合法，但：

```json
"publisher": { "@id": "https://learndiag.com/#organization" }
```

页面内**不存在**声明该 `@id` 的节点（全文 `@type: Organization` 仅 1 处，是 Article 的 `author` 内联对象；`@id` 仅 1 处，就是上面这个引用）。即 `publisher` 指向一个本页不存在的实体，schema 校验器会判为未解析引用，Google Article 富结果存在被判缺失的风险。

**建议**：内联 publisher 对象，或在本页补一个 `{"@type":"Organization","@id":"https://learndiag.com/#organization",...}` 节点。

### W-1 · 生产环境向每个页面注入 47KB 的 `.webmcp/bridge.js`，仓库无任何引用

> ✅ **已定性：非缺陷。** 该脚本是为做 GEO（生成式引擎优化）有意接入的能力，属预期设计，非供应链风险。后续如需下线或换源，走注入侧配置即可。

- `https://learndiag.com/.webmcp/bridge.js` 返回 200，47,616 字节（编译后的 `src/tool-pack.ts` 等）
- **仓库 `worker-src/`、`site/` 中检索 `webmcp` / `bridge.js` 零命中**——不在版本控制内
- 已排除本机环境干扰：
  - 第三方服务器抓取（allorigins，非本机网络）拿到的生产 HTML **含 `webmcp`**
  - `--no-proxy-server` 启动的浏览器同样加载该脚本
- 该脚本运行时会请求 `https://learndiag.com/mcp`（被 abort）

**原始疑问（已答复）**：曾疑为 Cloudflare 侧 Snippet / 账号级 Worker 注入的未受控脚本。产品负责人已说明：该脚本是为做 GEO（生成式引擎优化）有意接入的能力，**属预期设计，非供应链风险**。后续如需下线或换源，走注入侧配置即可，无需改动站点代码。

> 技术备查价值保留：该文件不在仓库版本控制内，若未来排查线上与仓库不一致问题，这是已知的、预期内的例外项，不必重复定位。
