## 1. 项目概述

**Triumph 是什么**：一个在线备考网站，帮助美国小学教师资格考试（Praxis 5001）考生练习真题（免费题库 969 题）、做水平诊断、预测通过概率。

**三个网址**（记住哪个是主站）：
| 网址 | 用途 | 谁看 |
|---|---|---|
| `https://learndiag.com` | **正式主站**（自有域名，2026-08-28 起） | 所有用户 |
| `https://trytriumph.de5.net` | 旧域名（已 301 到 learndiag.com，保留勿删） | 兼容旧链接 |

**一句话技术架构**（听不懂没关系，后面会拆开讲）：
- 网站本体 = 一堆**静态网页文件**（HTML/CSS/JS），放在 `site/` 文件夹里

  源码在 `worker-src/`，打包成 `site/_worker.js`
- 用户的注册信息、答题记录存在 Cloudflare 的 **KV 存储**（一个云端"小柜子"）里；题库与订单存在 **D1 数据库**

**当前所处阶段**：验证期（<1000 用户）。**2026-09-11 起付费已上线**（Creem 切到 live）：
Pro 订阅 **$19.99/月**、一次性诊断报告 **$9.99**，配合四档权限阶梯
（游客看前 6 题 / 免费登录看全部错题 / $9.99 一次性完整报告 / Pro 无限）—— 详见 §7。

## 4. 构建与部署

**先理解一个关键变化（很重要）**：
以前 `site/_worker.js` 是直接手写的，现在是**由 `worker-src/` 文件夹里的源码"打包"生成**的。打包的工具叫 esbuild。所以：

> **改了 `worker-src/` 里的任何文件 → 必须重新构建 → 才能部署。**

**完整的"改完代码上线"流程**（三步）：
1. **改代码**：改 `site/` 或 `worker-src/` 里的文件（怎么改见第 9 节"风险提示"）
2. **跑测试**：`npm test` —— 确认 `fail 0`
3. **部署**：`.\deploy.ps1`（注意前面有 `.\`，表示运行当前文件夹里的脚本）

`deploy.ps1` 会自动做三件事（你不用管细节）：
- ① 构建 worker（把 `worker-src/` 打包成 `site/_worker.js`）
- ② 检查你是否已登录 Cloudflare
- ③ 把 `site/` 文件夹上传到线上

**部署完成后**：
- 看到绿色 `=== DEPLOY OK ===` 说明成功
- 等 10-30 秒，打开 `https://learndiag.com` 强制刷新（`Ctrl+F5`）验证

**部署后必做的验证清单**（复制到终端逐条跑）：
```powershell
curl.exe -s https://learndiag.com/api/v1/health
```
- 如果你看到 `{"ok":true,"service":"triumph-api"...}` 说明后端正常 ✅
```powershell
curl.exe -s -o NUL -w "%{http_code}" https://learndiag.com/not-exist-page
```
- 如果你看到 `404` 说明不存在的页面正确返回"找不到" ✅（不是错误，是预期行为）

## 5. 环境变量说明

**环境变量 = 存密钥和配置的"小纸条"**。程序运行时读这些纸条来知道"用哪个邮箱发信"、"用什么密钥加密"。

| 变量名 | 干什么的 | 在哪配置 |
|---|---|---|
| `JWT_SECRET` | 登录凭证的加密密钥（**泄露/丢失 = 全站立即掉登录**） | Cloudflare 控制台（线上）+ `.dev.vars`（本地） |
| `EMAIL_FROM` | 发验证码邮件的发件人地址（**线上唯一非 secret 的变量**） | `wrangler.toml`（线上）+ `.dev.vars`（本地） |
| `RESEND_API_KEY` | 发邮件服务的密钥（Resend 服务） | Cloudflare 控制台 Secrets（线上） |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google 登录 | 同上 |
| `OPENROUTER_API_KEY` | AI 分析（诊断报告里的"趋势叙述"部分） | 同上 |
| `ADMIN_EMAILS` | 后台管理员白名单（逗号分隔可多个） | 同上 |
| `CREEM_MODE` | **支付环境开关：`live` 或 `test`** —— 决定代码打哪套 API | 同上 |
| `CREEM_API_KEY` | 支付服务密钥（当前为 live） | 同上 |
| `CREEM_PRODUCT_ID` | Pro 订阅产品 ID（$19.99） | 同上 |
| `CREEM_REPORT_PRODUCT_ID` | 一次性诊断报告产品 ID（$9.99） | 同上 |
| `CREEM_WEBHOOK_SECRET` | 支付回调验签密钥（当前为 live） | 同上 |
| `CREEM_TEST_API_KEY` / `CREEM_TEST_PRODUCT_ID` / `CREEM_TEST_WEBHOOK_SECRET` | 测试环境三件套（2026-09-11 切 live 后已不使用，保留可做回归测试） | 同上 |
| `TRIUMPH_KV` | KV 存储的"门牌"（**是绑定 binding，不是环境变量**） | `wrangler.toml`（已配好，不用动） |
| `TRIUMPH_D1` | D1 数据库（**是绑定 binding，不是环境变量**） | `wrangler.toml`（已配好，不用动） |

**线上现状（2026-09-11 用 `node tools/deploy-state.mjs` 实测）**：`triumph` 项目 production 共 **15 个变量**，
其中 **14 个是 `secret_text`、值读不出来**，只有 `EMAIL_FROM` 是明文。preview 环境 **0 个变量、无 bindings**。

**⚠️ 四条硬规矩**：

1. **Cloudflare 对 secret 只写不读** —— 控制台里只能看到名字、看不到值。**「名字在」≠「值对」。**
   要换值只能**覆盖重设**，没有"先读出来看一眼"这条路。
2. **绝不要用 API / 脚本批量提交变量**。那类接口是**整体对象语义**，一提交就会把读不到值的
   `JWT_SECRET` 等**清空** → **全站用户立即掉登录**。**只能在控制台逐条编辑**（逐条天然保留其他变量）。
3. **变量改了必须重新部署才生效**（对已有构建不生效）。这一步最容易漏，且症状最像"支付坏了"。
4. 改完变量、部署前后，各跑一次 `node tools/deploy-state.mjs` 核对。

**线上配置入口**（如果你需要改线上密钥）：
1. 打开 https://dash.cloudflare.com 登录
2. 左侧 Workers & Pages → 找到 `triumph` 项目
3. Settings → Variables and Secrets 里配置

**安全铁律**：
- ❌ 密钥**绝不能**写进 `site/` 里的任何文件（用户能直接看到）
- ❌ `.dev.vars` 不能提交到 GitHub（它已被忽略，别手动强制提交）
- ✅ 换密钥后，老密钥立即作废

## 6. 常见问题与排查（"如果你看到 XX 说明 XX"）

### 部署/运行类

| 你看到的现象 | 说明 | 怎么办 |
|---|---|---|
| `npm test` 显示 `fail 5` | 有 5 项测试坏了，说明刚才的改动破坏了某个功能 | 回滚改动（见第 9 节），或把报错信息发给 agent |
| 部署时提示 `未找到 wrangler` | 这台电脑还没装部署工具 | 让它自动装（脚本会执行），或手动 `npm install -g wrangler` |
| 部署时弹出浏览器要登录 | 你需要授权这台电脑连接 Cloudflare 账号 | 用你的 Cloudflare 账号登录即可 |
| 部署后线上页面是**旧的** | 浏览器缓存了旧版本 | 手机/电脑强制刷新（`Ctrl+F5`），或关掉页面重开 |
| `_worker.js` 报"文件被改"类错误 | 有人手改了生成文件 | 从 `worker-src/` 重新构建即可恢复 |
| `pnpm exec esbuild` 报 `ERR_PNPM_IGNORED_BUILDS` | pnpm 默认拦截了 esbuild 的安装脚本 | 运行 `pnpm approve-builds esbuild` 批准一次 |
| 改完 `worker-src/` 想确认没破坏行为 | 除了 `npm test`，还可跑新旧行为对拍 | `npm run test:parity`（对比备份版 worker，应全部 SAME） |
| 本地 `wrangler pages dev` 启动失败 | 端口被占用或参数写错 | 换端口：把 `--port 8799` 改成 `--port 8800` |
| `Email not configured` / `EMAIL_FROM not configured` 错误 | 发信配置缺失 | 检查 `.dev.vars`（本地）或 Cloudflare 控制台（线上）的 `EMAIL_FROM` |

### 功能类

| 你看到的现象 | 说明 | 怎么办 |
|---|---|---|
| 注册后收不到验证码邮件 | ① 邮件进垃圾箱 ② Resend 密钥失效 ③ 免费额度用完（每天 100 封） | 先查垃圾箱；再看 Cloudflare 控制台 Secrets 里 `RESEND_API_KEY` 是否还在 |
| 登录后提示"邮箱或密码错误" | 密码确实错了，或该账号未完成验证 | 先走"忘记密码"流程（若未上线则联系支持邮箱） |
| 用户反馈答题记录没同步 | 后端 `state` 接口出错 | 跑 `npm test` 看 `state` 相关测试；查线上日志 |
| 页面能打开但接口报错 | 后端挂了或部署失败 | 跑 `curl.exe -s https://learndiag.com/api/v1/health` 看是否返回 `ok:true` |
| `/api/v1/health` 返回 500 | Worker 崩溃 | 检查 `worker-src/` 最近改动，回滚后重新部署 |

### 怎么看线上日志（排查必学）

1. Cloudflare 控制台 → Workers & Pages → `triumph` → **Logs**（或 Realtime Logs）
2. 打开后访问一次网站，就能看到每次请求的记录
3. 红色/报错行就是问题所在；把内容截图发给 agent 分析

## 8. 数据接入位置

**用户数据存在哪**：Cloudflare **KV 存储**（`TRIUMPH_KV`）。你可以理解成一个"云端小柜子"，每个用户一个格子：

| 数据 | 存在哪 | 说明 |
|---|---|---|
| 用户账号（邮箱/密码哈希/是否验证） | KV `users:{邮箱}` | 密码不存明文，存的是加密后的"指纹" |
| 验证码 | KV `verify:{邮箱}` | 15 分钟过期 |
| 学习状态（答题记录/进度/计划） | KV `state:{用户id}` | 用户每次答题都会更新这里 |
| API 密钥 | KV `apikey:{密钥指纹}` | 开发者用的 |

**未来（规划中）会新增 D1 数据库**（更强大的"表格数据库"）：
- 订单、订阅记录、退款工单、题库后台管理、行为分析数据
- 理由：KV 适合存"单条记录"，但后台管理需要"查询/统计"（比如"查所有订阅用户"），这需要 D1
- 迁移策略：验证期用户少，先双写过渡再切换，不会丢数据

**你基本不需要手动碰数据**——后台管理（`/admin`）上线后，所有数据操作都有界面。万一需要手动查数据，也是在 Cloudflare 控制台的 KV/D1 面板里看，**不要直接改**。

## 9. 风险提示与回滚方式

### 高风险操作清单（操作前先看）

| 操作 | 风险等级 | 说明 |
|---|---|---|
| 改 `worker-src/` 任何文件 | 🔴 高 | 这是后端大脑，改错=全站接口挂掉。改前先跑 `npm test` 建立基线 |
| 改 `site/index.html` | 🟡 中 | 首页是门面，改坏影响最大；改完强制刷新验证 |
| 改题库数据 `data/questions-api.json` | 🟡 中 | 用户做题会受影响；改前备份 |
| 改 `.dev.vars` / 线上密钥 | 🔴 高 | 密钥配错=邮件发不出/登录全挂 |
| 部署前不跑测试 | 🔴 高 | 坏代码直接上线 |
| 手改 `site/_worker.js` | 🟡 中 | 会被下次构建覆盖，浪费功夫；改 `worker-src/` 才对 |
| 改 `cli/` 下的 CLI 工具 | 🟢 低 | 单独 npm 包，需走 `npm publish`；改完跑 `node cli/triumph-praxis.js --help` 自检 |

### 回滚方式（改坏了怎么恢复）

**方法一：回滚 `site/` 文件（最简单）**
- 备份在 `backups/` 文件夹里
- 把 `backups/` 里的对应文件复制回 `site/`，然后重新 `.\deploy.ps1`

**方法二：回滚 Worker（后端）**
- 原版 `_worker.js` 备份在 `backups/pre-modular-worker/_worker.js`
- 恢复：把该文件复制回 `site/_worker.js`，然后 `.\deploy.ps1`
- （这是模块化改造前的完整原版，作为最后保险）

**方法三：回滚整个部署（最彻底）**
- Cloudflare 控制台 → Workers & Pages → `triumph` → Deployments
- 找到上次正常的部署版本 → **Rollback**（回滚）
- 网站会立即恢复到那个版本，约 1 分钟生效

**回滚守则**：
- 每次部署前，`git` 里先提交一次（`git add -A; git commit -m "部署前快照"`），这样随时能回到任意历史版本
- 线上出问题 → 先回滚 → 再排查 → 不要一边改一边猜
