**这个站在 2026-09-22 发生了一次站点级塌陷：收录 URL 从 25 条腰斩到 13 条，日展示从 ~40 次掉到 ~3 次，之后再没回来。**

## 5. 🔴 线上实测发现的 5 个真问题

### P0-1 `www.learndiag.com` 全站 522（CF 连不上源站）
```
https://www.learndiag.com/            -> 522
https://www.learndiag.com/diagnostic  -> 522
http://www.learndiag.com/             -> 301 → https://www.learndiag.com/  → 522
https://learndiag.com/                -> 200 ✅
```
www 与裸域 DNS 同 IP，**每个 www URL 都是硬错误**。Google 抓到任何一个 www 变体都会记一条错误。
这条 Semrush 在 10-14 就报了（「5xx errors on https://www.learndiag.com/」），**至今没修**。
**修法**：要么解绑 www 的 Pages 自定义域名，要么在 DNS/zone 层把 www 做成指向裸域的 301（zone 级 API 读不到，见红线 25/26 → 走 dashboard 操作）。

### P0-2 `sitemap lastmod` 全线过期 —— 策略写了但没做
《站点收敛策略》§5 第 3 条：「`lastmod` 全部改成实际更新日」。实际 sitemap 的 lastmod：

| lastmod | 条数 | 说明 |
|---|---|---|
| 2026-08-30 | 2 | `/`、`/praxis-5001-registration-guide` |
| 2026-08-22 | 5 | /about /contact /privacy /developers |
| 2026-08-24 | 1 | /terms |
| 2026-08-25 | 1 | /mistake-log |
| 2026-10-09 | 9 | 批次A 那天统一刷的 |
| **≤ 2026-09-01** | **8** | 🔴 全部停在塌陷之前 |

其中 `/` 的 lastmod 还是 08-30，而首页在 10-18 刚被「装饰层 v1.2 铺满全站」改过。
**对一个「Google 几乎不抓」的站，喂过期 lastmod 等于告诉 Google「优先抓那 9 个 10-09 的，其余别碰」——正好和收敛目标相反。**
批次 A 只做到「每条都有 loc + lastmod」，没做到「lastmod 是真实更新日」。

### P1-3 两个真 404 + 一个 410
| URL | 状态 | 情况 |
|---|---|---|
| `/praxis-5001-pennsylvania-requirements` | **410** | 09-27 退役。**它有 41 展示 / 位置 19.54** —— 策略文档 §8 第 1 条明写「不要 410 掉州页面，它们有排名，301 合并不是删除」，这条自己破了自己的规矩。410 不传递权重。 |
| `/praxis-5002-vs-8006` | **404** | 站上真实页面是 `/praxis-8002-vs-8006`（5002 ↔ 8002 写错了）。**站内 0 处引用** → 纯历史遗留 URL，应该 301 过去而不是 404。 |
| `/passing-scores` | **404** | 站内 0 处引用（`four-gate-strategy` 里只是文字提到「our passing-scores page」，不是链接）。同样应 301 到 `/score-calculator`。 |

（GSC 报的 3 条 404 正好对上这 3 个。）

### P1-4 公开 API 的 JSON 端点可被抓取，robots.txt 没拦
`/openapi.json` 对外公开列了 14 个路径，robots.txt 里**没有 `Disallow: /api`**。实测 GET：

| 端点 | 状态 | 大小 | 问题 |
|---|---|---|---|
| `/api/v1/questions` | **200** | 15,845 B | 🔴 原始题库 JSON，与 practice 页正文**重复内容** |
| `/api/v1/questions/random` | **200** | 3,209 B | 同上 |
| `/api/v1/stats` | 200 | 975 B | JSON 页，可被索引 |
| `/api/v1/meta` | 200 | 1,385 B | JSON 页 |
| `/api/v1/health` | 200 | 277 B | JSON 页 |
| `/api/me` | **401** | — | 🔴 **GSC 报的那 1 条 401 就是它**（被 openapi.json 暴露 → Google 抓 → 401） |
| `/api/state` | 401 | — | 同类 |
| `/api/v1/keys/verify` | 401 | — | 同类 |
| `/api/register` `/api/login` `/api/verify` `/api/resend` `/api/logout` | 405 | — | 不可抓 |

**为什么重要**：
1. 5 个 200 的 JSON 端点**可以进索引**，属于「非 HTML 页面」，会稀释站点主题、占用抓取预算；
2. `/api/v1/questions` 15.8 KB 是**题库原文**，和 `/praxis-8002~8006-practice` 页正文**构成重复内容面**——在「重复内容 / 规模化内容」这类判定上，这是自伤；
3. 3 个 401 端点让 GSC 的「严重问题」列表长期挂红。

**修法**（低风险）：`robots.txt` 加 `Disallow: /api/` + API 响应加 `X-Robots-Tag: noindex`。
（注意：这不违反「不动 robots.txt」的约定——那条约定针对的是**不要动 AI agent 放行规则**；`Disallow: /api/` 不影响 Googlebot 抓 HTML 正文。）

### P2-5 3 条 401 里 2 条还没被 Google 发现
GSC 只报了 1 条 401（`/api/me`），`/api/state`、`/api/v1/keys/verify` 还没进 Google 视野。
按 P1-4 一起处理即可。

## 8. 建议动作（按 ROI 排序）

> 🔴 **排序逻辑变了**。上一版（10-18 策略文档）的隐含假设是「问题是页面质量，先把面收窄」。
> 本次数据证明：**当前的第一瓶颈是「Google 不抓这个站」**，第二瓶颈才是质量。
> 任何「改页面质量」的动作，**在 Google 不来抓之前都是无效的**（没有抓取 = 没有重新判定 = 不可能有新排名）。
> 所以下面的动作全部围绕「**让 Google 多抓、别抓错的东西**」。

| # | 动作 | 依据 | 风险 | 工作量 |
|---|---|---|---|---|
| **A** | **修 sitemap lastmod 为真实更新日**（18 条逐条对） | 策略文档已写但没做；对「不被抓」的站是反向信号。当前 8/18 页 lastmod 停在 08-22~08-30 | 无 | 30 分钟 |
| **B** | **修 www 522**（解绑或做 301） | 全站硬错误；Semrush 10-14 就报了，至今没修 | 需 dashboard | 30 分钟 + 用户操作 |
| **C** | **`/api/*` 加 robots Disallow + `X-Robots-Tag: noindex`** | 8 个 API 端点（5×200 JSON + 3×401）在吃抓取预算；`/api/v1/questions` 15.8KB 题库 JSON 与 practice 页正文构成重复内容面 | 无 | 1 小时 |
| **D** | **PA 州页 410 → 301**；`/praxis-5002-vs-8006`、`/passing-scores` → 301 | 3 条 404/410 已被 Google 收录为错误；PA 页有 41 展示 / 位置 19.54，410 不传递权重 | 低 | 1 小时 |

| **F** | **给 15 条「从未抓过」的 URL 补内链** | 15 条从未被抓 = 索引状态未定。`tools/audit-inlinks.mjs` 就是干这个的 | 低 | 待定 |
| **G** | 继续观察，**不新增页面** | 策略文档 §7 验收线 | 无 | 0 |

### ⚠️ 关于「6 周观察窗」的修正建议

策略文档 §7 定的验收窗是「部署后 6 周（到 12-01）」，判据是「7 页里有 ≥3 页变成已收录，且 6 周展示 ≥ 500」。

**按当前抓取速率，这个判据在 12-01 前几乎不可能被满足**：
- 14 天抓 10 个 URL → 6 周约 30 个 URL
- 18 个保留页里 Google 大概率只能覆盖 60%
- 每页展示历史峰值也就 143 次/3 个月，18 页合计展示 ~500 需要接近历史最好水平

→ **建议把「6 周」从「日历时间」改成「Google 至少重抓完 18 页之后再计时」**，或者按 A~F 修完后**重新起算**。
否则会在 12-01 得出「收敛无效」的错误结论，而实际只是「实验还没跑完」。

**明确不要做**（沿用策略文档 + 本次数据）：
- 不要在观察窗内新增任何内容页（会污染收敛实验）；
- 不要按 trust 分逐页补「可信信号」—— 已有硬证据表明 trust 与收录**无相关性**（档 2 收录率 0%）；
- 不要买外链 / 进目录站 / 刷 GSC；
- 不要为「改 md 通道读到的邮箱」去动 zone 级混淆开关（md 走 `text/markdown`，本来就不混淆）；
- **不要把「已抓取-尚未编入索引 31 条」当成 31 个待修的 bug** —— 既然 Google 抓了它却不要它，多半是质量判定，不是技术问题。

## 9. 需要老户决定的三件事

1. **www 怎么处理**：解绑 Pages 自定义域名（最省事，但要先确认 zone 层能否承接 www→裸域 301），还是保留 www 绑定并修源站连通性？
2. **观察窗怎么定**：日历 6 周（到 12-01）大概率跑不完实验。是改成「Google 重抓完 18 页再计时」，还是 A~F 修完后**重新起算 6 周**？
3. **这个域名还要不要继续做 SEO**：《站点收敛策略》§7 已经写了止损线（「收录还是 4/7 左右、展示没变化 → 停止投入，这个域名只做产品不做 SEO 流量」）。
   照现在的数据看，**止损线其实已经触发了** —— 10-22 的已收录率 10.6%、4 天内 0 改善。
   但 A~F 里 A/C/D 三项是**一次性技术债**（lastmod 过期、API 裸奔、3 条死链），修不修都要做，因为它们**不只在 SEO 生效**（lastmod 影响 AI 爬虫的抓取节奏；`/api/v1/questions` 裸奔是重复内容面；死链影响 AI 爬虫的信任评估）。
   → **建议：做技术债 A~F，SEO 期望值调到「不亏本」而不是「要增长」**，把主要精力放回产品侧（付费转化、题库、用户留存）。
