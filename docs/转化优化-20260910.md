## 一、三个不成立的前提（最重要，先看这个）

### 1. P0-1 的「Creem 后台 declined 率」查不了，而且大概率不是真失败

- **Creem 目前是测试模式**（`HANDOFF.md §5`、`项目计划完成情况-20260906.md` 都写着「Creem 支付接入（测试模式）」「Creem 审核中」）。
  测试模式没有真实扣款，**根本没有 declined 率可读**。
- 我也没有 Creem 后台的访问权（`CREEM_*` 是 Cloudflare Pages 的 Secret，非交互读不到，仓库里只有占位）。
- 至于「社群 2026-05 多人反馈 Creem 掉单大增」—— 我找到了这件事的**真实成因**，而且它不是掉单：
  多个出海卖家在同一时段看到 Creem 后台「大量订单标注失败」，Creem 客服的答复是
  **平台把原来笼统归为「处理中」的状态拆成了「待验证 / 待结算 / 失败」等细分标签**，
  交易流程、扣款记录、最终到账**全都没变**，只是前端展示逻辑改了。
  （来源：10100.com《大批出海卖家中招!Stripe、Creem 近期收款失败,真相来了》）
  → 社群里的「掉单大增」极可能是**这个显示口径变化造成的误判**，不是真的丢单。

**但我没有停在「查不了」**：我把支付链路代码对着 Creem 官方 webhook 文档逐字段审了一遍，
**发现 6 个真实的静默掉单缺陷**（含一个白拿 Pro 的漏洞）。已全部修复 + 加回归测试，见第三节。

### 2. 「差 8 分」和「3 个短板」算不出来

- **全站没有任何州的及格线数据**。我 grep 了 `cut_score` / `cutScore` / `stateLine` / `state_line`，
  `site/` 和 `worker-src/` **零命中**；也没有「用户所在州」输入。
- 诊断页用的是 demo 模型里硬编码的**典型线 160**（`DM_estimateScore: 140 + acc*40`）。
  真实数字 ×，写死「差 8 分」= 给每个用户编一个假数字。
- 「3 个短板」也不成立：诊断**只算出一个 weakest gate**（四科里最低的那一科），算不出「3 个」。

**我的处理**：把「差 X 分 → K 个短板 → $15/mo」做成**动态模板**，
X 由用户真实分数算（160 − 实际分），K 由四科真实正确率算（低于 50% 的科数），价格用真实的 $15/mo。
并且每条摘要都带一句 `Your state sets the real line, not ETS` + 指向州线页 —— 不冒充用户所在州的线。

### 3. 「重考 $130」是错的，全站 6 处都在用

这是本轮**最值得单独拎出来的一条**。站点自己的重考指南写的是
「5003 product page listed **$64** and the combined 5001 listed **$180**」——
但 `about.html` / `index.html` / `practice.html` / `praxis-5001-four-gate-strategy.html`(×2) / `score-calculator.html`
一共 6 处对外讲的是「**$130**」。

我对着 **ETS 官方州要求页**核实（Louisiana / Connecticut / Delaware / New Hampshire 四个州口径一致）：

| 项目 | ETS 官方价格 |
|---|---|
| Elementary Education: Multiple Subjects（5001，合并四科） | **$180.00** |
| 单科 subtest（5002 / 5003 / 5004 / 5005，每个） | **$64.00** |
| 重考 | 按当前原价重新注册，**没有重考折扣** |

$130 是**别的 Praxis 科目**的价格（5162 Algebra I、5164 Middle School Math、5442、5589、5236 等都是 $130），
大概率是从那里串进来的。

→ 用 $130 做价格锚点是**双重损失**：既低估了重考的真实成本（锚点变得没有说服力），
又在一个紧接着 ETS 引用的页面上放了一个和 ETS 对不上的数字。
**6 处已全部改为 $180（合并 5001）/ $64（单科）**，全站已无残留。

## 三、P0-1 实测：支付链路的 6 个掉单缺陷

方法：把 `worker-src/billing.mjs` 对着 `docs.creem.io/code/webhooks` 的**逐字 payload** 逐字段核对。
（顺带确认了一件事：代码里原本那个 `obj = evt.object || evt.data || evt` 是对的 ——
网上有开发者在 `event.data.customer` 上踩过坑，Creem 的真实结构是 `event.object`，我们没踩。）

### 缺陷 1｜webhook 不管成败都返回 200 → 真·隐形掉单 ★最严重

原代码里 D1/KV 写失败被 `d1Exec` 的 `catch` 吞掉，日志一打，`hBillingWebhook` 照样返回 `{ok:true}`。
Creem 只在收到**非 2xx** 时才重投（30s / 5m / 30m / 6h，共 5 次），
所以 D1 或 KV 抖一下 = 用户钱扣了、KV 里没写 `plan=pro`、前端永远显示 FREE，**而且日志里看不出异常**。

**改法**：权益写入（KV）失败 → 抛错 → 500 → Creem 重投。
D1 只是订单镜像（不是权益来源），失败降级不阻断权益，但会在响应体里回传 `d1_degraded: true`，在 Creem 后台一眼可见。

### 缺陷 2｜没配 webhook secret 时**完全跳过验签** → 任何人可白拿 Pro ★安全

原代码是 `if (secret) { ...验签... }` —— secret 没配就直接放行。
攻击者只要 POST 一个
`{"eventType":"checkout.completed","object":{"customer":{"email":"随便一个已注册邮箱"}}}`
就能给自己开 Pro。

**改法**：fail closed —— 没有 secret 直接 503 并留日志（Creem 会重投，secret 配好后自动补投）。

### 缺陷 3｜`current_period_end` 字段名是错的

Creem 的字段是 **`current_period_end_date`**（`subscription.paid` payload 里明确写着）。
原代码读 `sub.current_period_end` → **永远是 null** → `upgrade.html` 的「Renews on —」一直是破的。

**改法**：优先读 `current_period_end_date`，兼容旧名。

### 缺陷 4｜取消订阅**立刻降级** → 违反自己发布的 Terms

`Terms of Service §4` 明确写着：「Cancellation takes effect at the end of the current billing period;
you keep Pro access until then.」
但原代码在 `subscription.canceled` 且 `status === 'canceled'` 时**立即**把 `plan` 设成 `free`。
而真实 payload 里 `subscription.canceled` 的 `current_period_end_date` 是**未来**时间。

→ 用户第 2 天取消，立刻丢掉剩下 28 天已付费的访问权。这是「反向掉单」，直接换来客服工单和拒付。

**改法**：只有 `current_period_end_date` 真的过期（或拿不到该字段）才降级，否则保留 pro。
另外补上了 `subscription.scheduled_cancel`（Creem 的「期末取消」事件，原来完全没处理）。

### 缺陷 5｜`dispute.created`（拒付）完全没处理

Creem 有 13 个事件类型，拒付以前一行都没有 → 钱被追回了系统里查不到。
**改法**：落库为 `type='dispute'`，同时收回 Pro。

### 缺陷 6｜`refund.created` 只改订单状态，不收权益

退款了但用户还是 Pro。
**改法**：退款后同步降级 `plan='free'`。
（顺带修了 `refund.created` 的 payload 取值路径 —— 它把 customer 嵌在 `obj.checkout` 下面，不在 `obj.customer`。）

### 回归测试

新增 `test/p1-billing-webhook-drop.test.mjs`，用官方逐字 payload 覆盖 10 个场景，已接进 `npm test`：

```
✓ checkout.completed 按 object.customer.email 授予 pro
✓ D1 绑定缺失时权益照发，且以 d1_degraded 暴露（不静默）
✓ 同一事件 id 重投保持幂等
✓ subscription.active（无 metadata）仍能按邮箱授予 pro
✓ 取消但计费周期未走完 → 保留 pro（对齐 Terms §4）
✓ 计费周期已走完的取消 → 降级 free
✓ 未配置 webhook secret → 503 且不授予权益（拒绝伪造事件）
✓ 签名不符 → 401
✓ KV 写失败 → 5xx 触发 Creem 重投（不再假装成功）
✓ 付款邮箱没有对应账号 → 以 skipped_no_user 暴露（不静默）
```

**还需要你做的两件事**（我做不了）：
1. 去 Creem 后台 Developers → Webhook，确认 **production 和 test 的 webhook secret 都配了**、且 endpoint 是 `https://learndiag.com/api/billing/webhook`。
   配之前我新加的 fail-closed 会让 webhook 返回 503（这是有意的：宁可吵，不要静默）。
2. 用 Creem 的测试卡把「付款 → 回跳 → 看到 PRO」整条链路**手动跑一遍**。
   代码里那句注释说 payload 结构是「照 webhook 文档」写的 —— 也就是说**从来没有真跑过真实 webhook**。
   这正是最典型的隐形掉单来源。

## 四、P0-2 / P0-3 / P1-4 / P1-5 具体改了什么

### 为什么走 DOM 钩子而不是直接改页面

`site/diagnostic.html` 的 `<script type="text/babel">` 是压缩过的单文件 React app。
项目里 `js/signup-hook.js` 已经立了规矩：**结构性改动一律用 DOM 钩子，React 包保持字节不变**，
这样以后重新构建不会把改动冲掉。我照这个约定新加了 `site/js/conversion-hook.js`（约 180 行），
只在 `diagnostic.html` 加了一行 `<script src="js/conversion-hook.js?v=1">`。

### P0-2 · 结果页只留一个主按钮

锁定态（未登录）原来主按钮是 `Log in to unlock`，右边并排一个 `$15/mo`。
那个价格标签是**竞争元素**——用户还没登录，先看到要钱，直接劝退。

- 主按钮文案 → **`Log in to save your report`**
- 登录态**隐藏** `$15/mo` 标签（价格留给升级态讲）
- 全区只剩 **1 个 `.btn-primary`**（已断言）
- 保留 Share（`.btn-ghost` 二级按钮）—— 这是我的判断，见第七节说明

### P0-3 · 解锁瞬间的价值摘要

**没有「注册成功页」这个东西**：`login.html` 登录/注册成功后直接 `location.href = next`（默认 `/dashboard`）。
而转化意愿最强的那批人（做完诊断 → 内联注册）根本不离开诊断页 ——
`signup-hook.js` 就在原页面上注册 + reload 解锁。

所以我把这条文案放在**真正的成功瞬间**：解锁后的 `.unlocked-box` 里，紧跟 `<h3>` 之后插入摘要：

```
You're 7 points below the typical 160 line, with 3 of 4 subtests under it.
Pro is $15/mo — cheaper than the $180 and 28 days a retake costs.
Your state sets the real line, not ETS — [check your state's line]
```

三个数字**全部是真实算出来的**（用户实际分数 / 四科实际正确率 / 真实价格），
不是写死「差 8 分 → 3 个短板」。

### P1-4 · 「差 X 分」处插付费点

**计算器页**（`site/score-calculator.html`）：结果框正下方加了一个 `#gap-cta` 付费块，
**只在低于所填线时才露出**，标题直接用真实的差距：`You're 7 points short of your 157 line.`
（这里用户自己填了线，所以数字是诚实的，比诊断页更有底气。）

**诊断报告**：付费点的抬头就放在 `差 X 分` 的位置 —— 大分数 → pass probability → 分科条 → 付费墙，
不等到页面底部。

### P1-5 · 价格锚点（数字已纠正）

- `upgrade.html`：`$15/month` 右侧 → **`vs $180 to retake the full 5001`**
- 诊断页锁定态：CTA 区锚点 → `A full 5001 retake costs $180 + 28 days`
- 计算器页：同上
- 顺带纠正全站 6 处 `$130`

### 额外加的一个支付体验修口

`billing.mjs` 的结账回跳改成 `/upgrade.html?checkout=done`，
`upgrade.html` 据此**轮询 `/api/me` 最多 10 次**，等 Pro 落权后再刷新一次。
解决「钱付了、页面还写着 FREE、用户以为掉单」——这才是用户视角的掉单。
轮询超时会显示「已收到付款但确认还没到，几分钟内会到 / 联系我们当天处理」，而不是干等。

## 五、P2-6 只做了一半，以及为什么

### 做了：把**已经存在**的 14 天退款政策摆到台面上

站点**已经有** 14 天退款政策，写在 `terms.html §5` 和 `contact.html`，但**付费页面上一个字都没提**。
这是个免费的信任资产，我把它加到了 `upgrade.html` 的价格区下方。

### 没做：「7 天退款」—— 这会是**降级**

你要的 7 天比站点现有的 **14 天更差**。按 7 天写等于主动把已经承诺的消费者保护砍掉一半，
既降低转化（更短的窗口 = 更强的压迫感 = 更高犹豫），又是个没有理由的自伤。
建议：**就用 14 天**，把它写显眼。

### 没做：「Pass Guarantee」—— 这个需要你先做决定

不建议现在写。三个理由：

1. **它是一个有法律约束力的承诺**，不是文案。写「不过退钱」就意味着要兑现——
   而 Pro 现在的权益列表是「Adaptive daily tasks / Pass-probability tracking / SRS cards /
   Early access to all new Pro study tools」，其中相当一部分还是规划态。
   拿还没做完的东西做「保证通过」，是真广告法风险，也是拒付来源。
2. **Creem 是 Merchant of Record**，退款流程归它管。跨 MoR 的「保证」需要先在 Creem 后台把退款规则配好，
   再动文案。顺序反了会变成「承诺了但退不了」。
3. 竞品 TeacherTestPrep 提供的是「If you don't pass, you don't pay」——**那是它们的在线课程**，
   有课时、有作业、有学时。我们是一个 $15/月 的自助工具，没有同等交付物支撑同一个承诺。

我在 `upgrade.html` 里放的是一句**诚实且能兑现**的替代说法：

> No pass guarantee: we won't promise an exam result no prep tool can control,
> but we will not keep money for a month you didn't use.

如果你确认要做 Pass Guarantee，**先定这三件事**，我再上文案：
保证范围（哪些 Pro 功能必须用满）、失败判定标准（ETS 成绩单怎么提交）、退款窗口（到期后多久）。

### 「A/B 测试」也做不了

全站没有任何 A/B 基础设施（没有分流、没有埋点分组）。而且现在**真实用户约等于 0**
（9/6 的检查：注册 4 个测试账号、零转化）——
**在 n≈0 上做 A/B 测试得到的任何结论都是噪声。** 先有流量，再有 A/B。

## 六、P2-7 没做，以及为什么

「收窄免费版功能一格、压制『免费够用』心理」——现在是**反着做**的时候：

1. **当前策略是你自己定的**：`HANDOFF.md` 写着「付费：Creem 审核中，**免费功能全开放（<1000 用户验证期）**」。
   收窄免费版 = 推翻这条策略，而推翻的依据（「免费够用」的转化损失）现在**一个数据点都没有**。
2. **免费诊断就是唯一的漏斗入口**。收窄它等于在最顶部掐流量 —— 而我们缺的正是流量，不是转化率。
   在一个每天个位数访客的站上收窄免费版，结果只会是「访问量不变、注册量下降」。
3. 「免费够用」这个诊断本身也还没被验证。要先有足够的注册用户，才能看出「注册了但不付钱」的比例，
   再判断是不是免费版太厚。

**如果一定要动**，最小安全版本是：**加配额不减能力** ——
免费版每天的 AI 错题解析从 3 次降到 2 次，其余不动。这个改动可逆、不影响漏斗顶部，且能测出付费意愿的斜率。
要做的话跟我说。

## 七、顺带发现的两个问题（不属于本次 7 项）

### 1. 「注册转化率太低」这个前提本身需要修正

按 9/6 的实证检查：**注册 4 个账号、全是测试账号、零真实转化、真实独立用户 < 30**。

**n=0 的时候算不出转化率。** 现在漏斗上每一格都是「0/几」，
P0-2 改一个按钮文案带来的预期收益，远小于「让 100 个真人到达诊断结果页」。

这不是说 P0-2 不该改（改完是对的，且改一次永久有效），
而是说：**如果目标是本月见到更多注册，瓶颈在分发，不在结果页。**

### 2. 我保留了 Share 按钮，没按字面「只保留一个主按钮」删

`ShareScore` 现在是 `.btn-ghost`（二级按钮），不是主按钮，所以不违反「只保留一个主按钮」。
更重要的是：按你的社区分发结论，**图片/分享卡片是唯一能规模化的形态**，
而分享卡片正是从这里长出来的。把它删了会砍掉唯一的增长回路。
如果你想连 Share 也收掉，跟我说，我 5 分钟就能改。
