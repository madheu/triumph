## 二、21 个访客 0 注册：不是文案问题，是 CTA 在页面最底部

先给生产数据（D1 `product_events`，2026-09-03 → 09-10）：

```
test_view        50   ←  21 个访客
test_start       29   ←  11 个访客
question_answer 106   ←   7 个访客
test_complete    16   ←   7 个访客
result_view       2   ←   2 个访客   ← 埋点 bug，见下
signup_prompt_view / signup_start / signup_success  =  0（一条都没有）
```

来源：`direct` 15 人 / 169 事件，`paid` 6 人 / 46 事件（`paid` = 带 gclid/fbclid/utm_medium=cpc，说明在投广告）。

### 漏斗断点

```
21 访客  ──52%──▶  11 开始  ──64%──▶  7 做完  ──0%──▶  0 注册
```

**真正的问题在最后一段：7 个人做完了 12 题的诊断，没有一个人注册。**

### 为什么是 0 —— 两个叠加的原因

**原因 1（主因）：注册 CTA 在页面最底部，没人滚到那里。**

诊断结果页的渲染顺序是：

```
成绩大字 + 及格概率          ← 用户在这里就停了
四科分项条
"你最弱的一环"
错题回顾（每错一题渲染一大块，12 题时能有 2000px+）
──── 付费墙 / 注册卡片在这里 ────   ← 实际位置
```

`signup_prompt_view` 用的是 `IntersectionObserver` + `threshold: 0.5`——**卡片进入视口一半才算"看见"**。这个数字是 0，只有两种可能：要么卡片没渲染，要么**没人滚到那儿**。而 7 个人 `test_complete` 是有的、`signup_start` 是 0，说明是后者。

这和 `result_view` 只有 2/16 是同一个现象的两面。

**原因 2：`result_view` 的 12.5% 是埋点 bug，不是真实行为。**

`.report` 元素高 2000px+，视口 800px，可见比的上限 = 800/2000 = **0.4**，永远达不到 `threshold: 0.5`。所以 `result_view` 系统性漏报（上一轮已修，改成自适应阈值）。

> 修正一下：**不做这个修正的话，你会以为只有 2/16 的人看到了报告，实际是 7/7。** 判断方向会被带偏。

### 提升注册转化的建议（按杠杆大小排序）

**P0 · 把注册入口从页面底部搬到结果出现的位置**

具体的：`test_complete` 触发后立刻在**成绩大字正下方**放一个轻量入口，而不是等用户滚到 `.paywall`。这是唯一能直接改变"7 做完 → 0 注册"这段的措施。

- 已验证的支持证据：`paid` 来的 6 个人里有 **2 个做完了完整 12 题**（33% 完成率，对 12 题诊断来说不算差）。他们不是不感兴趣，是没被要求做任何事就离开了。
- 移动端占完成者的 3/4，长页面滚动成本更高，这个改动对移动端收益最大。

**P1 · 在"最弱的一环"那句话旁边给出口，而不是在页面末尾**

现在最弱科目那句话是纯陈述（"your weakest gate is Mathematics"），没有任何动作。紧跟着给一个"针对这一科怎么补"的入口，转化路径会短很多。

**P2 · `?subtest=` 落地页单独看**

1b7b3753 是从 `praxis-8006-practice` 进来的、1b7b3753 只走到 `test_start` 就没了。8006 的流量进诊断后的表现值得单独切一刀（等 9/10 的埋点修复上线后有数据）。

**P3 · 不要在 n=21 上做 A/B**

21 个访客、7 个完成，任何文案 A/B 的结论都是噪声。这一轮该做的是**结构性改动**（把入口搬上来），不是文案微调。

## 三、文案：已去掉「差 8 分 → 3 个短板」

### 已实施（`site/js/conversion-hook.js`）

原来写的是：

> "You're **12 points** below the typical 160 line, with **3 of 4** subtests under it."

改成：

> **You may be one weak spot away from passing.**
> Your weakest gate is `Mathematics` at `38%` — and it is the one dragging the rest of your result down. The demo model puts you about `12 points` under the typical 160 line.
> Pro is **$15/mo** — and one more retake costs **$180** plus 28 days.
> **14-day refund** on every paid plan — ask within 14 days of the charge and we return it, no questions.
> Your state sets the real line, not ETS — check your state's line.

**为什么换掉"3 个短板"**：差值（12 分）算得出来，短板**个数**算不出来。`DM_Report` 自己只算**一个**最弱科目（`min(accuracy)` 取最小），"3 个"是把一个真实结论硬摊成三个。宁可只讲一个真的——而且"只差这一个"这个叙事**更窄、更有指向性**，比"你有三个问题"更像"就差这一步"。

### 5.2 「未解锁绝对不能渲染」——做成了结构性保证

这条是整个第 5 项里最重要的约束，所以我用了**服务端生成**而不是前端 `if`：

```
浏览器                          worker
  │  POST /api/diagnostic/report
  │  { attempt_id, visitor_id, answers }
  ├──────────────────────────────▶
  │                          resolveEntitlement()
  │                          ├─ Pro? 查 KV users:<email>.plan
  │                          ├─ 凭证? 查 KV report_credit:<visitor_id>
  │                          └─ 都不是 → 402
  │  ◀──── 402 ─────────────────┤  { error: {code:'report_locked'},
  │                                  options:['login','purchase'] }
  │                              ← 响应体里一个字的报告内容都没有
  │
  │  （有权时）◀── 200 ──────────┤  完整报告 JSON（服务端算完 + AI 写完）
```

**前端的 `report.js` 里没有任何"本地拼一份报告"的代码路径。** 拿不到数据就不可能渲染错。

回归测试直接断言这一点（`test/diagnostic-report.test.mjs`）：

```
✓ 免费访客：POST 报告返回 402，且响应体里没有任何报告内容
  · 逐项检查 summary / radar / narrative / misses / knowledge_points /
    subtests / score / pass_probability / headline 全部不出现在响应里
  · 额外断言响应体不含 140 / 160 / 180 任何一个分数
✓ 免费访客连续请求也不会拿到报告（门控在服务端，不靠前端 if）
✓ 一次性购买凭证：可出报告，且凭证只对那一份 attempt 有效
✓ 凭证写入失败必须 5xx
```

另外**判分也收归服务端**：客户端传 `correct: true` 会被完全忽略。

```
✓ computeReport：客户端传的 correct 字段一律被忽略（判分以服务端题库为准）
  全错就是全错，客户端说对不算 → score 140
✓ computeReport：题数反映的是实际匹配到的答卷（防前端虚报）
  不在题库的题、选项越界的题一律丢弃
```

### 5.3 九维雷达图 + AI 趋势分析

**维度（4 个你指定的 + 5 个扩展，全部 0-100，越高越好）：**

| # | 维度 | 来源 | 计算 |
|---|---|---|---|
| 1 | 答题节奏 Pace | **每题时间**（你指定） | 中位数落在 45–75s 满分，过短（<25s）判草率，过长判卡顿 |
| 2 | 知识点反应 Knowledge | **知识点反应**（你指定） | 触达的每个 category 准确率求均值 |
| 3 | 错题负荷 Error load | **各科错题数量**（你指定） | 按科目规模加权的正确率 |
| 4 | 弱项集中度 Focus | **错题点**（你指定） | 错题越集中在一个知识点，风险越高 → 分越低 |
| 5 | 作答稳定性 Steady | 扩展 | 四科准确率的标准差（越小越稳） |
| 6 | 四科均衡 Headroom* | 扩展 | 最弱一科拉到满分能补多少分 |
| 7 | 猜测抑制 No guessing | 扩展 | 用时 <15s 且答错的比例（秒答惩罚） |
| 8 | 动量 Momentum | 扩展 | 与上一次诊断的分数变动（±20 分打满） |
| 9 | 就绪度合成 | 扩展 | 上述加权综合 |

> 说明：3 与 9 在设计上没有冗余——3 只看"错了多少"，6/8 看"往哪补最划算"和"在不在进步"。9 是给"我就想看一个数"的人的总分。
> `measured: false` 的维度（比如整场没有用时数据）会画成**灰色虚线轴 + 标注 n/a**，不伪造分数。

**技术实现**：雷达图是**手写内联 SVG**（`report.js` 的 `radarSvg()`），没有引任何图表库——站点跑在 Cloudflare Pages 上，为一张图引一个 CDN 库不划算，九条轴也就几十行代码。

**AI 的边界**：**分数全部确定性计算，AI 只写叙述。** 同一份答卷每次必须给出同样的雷达图——模型会漂，分数不能飘。AI 的输出 schema 固定：

```
{ headline, trend, pace_read, knowledge_read, miss_read, risk,
  weak_points: [{topic, why, fix}], next_actions: [] }
```

模型全挂（429/超时/坏 JSON，三段模型链依次降级）时回退到**确定性叙述模板**，报告依然完整，只是页面上多一行小字说明"本次由规则引擎撰写，所有数字不受影响"。**最坏情况等于现状，不会更差。**

### 5.4 「格式化输出、真实反映做题数量」

报告头部固定一行：

> This report was built from **12 questions** you actually answered — **7 correct**, **58.3% accuracy**. Your previous diagnostic estimated 152.

这三个数**全部由服务端实际匹配到的答卷算出**，前端传什么都不影响（有测试守着）。报告可下载为自带样式的单页 HTML（含同一张雷达 SVG），也可直接打印存 PDF。

### 5.5 Dashboard「SETTING · PRACTICE」新增诊断题目数量

`site/dashboard.html` → Settings → **PRACTICE** 新增一行：

> **Diagnostic length** — How many questions the free readiness diagnostic draws, split evenly across the four subtests. Longer runs give a steadier estimate.
> `[ 8 ] [ 12 ] [ 16 ] [ 20 ] [ 24 ]`（默认 **12**）

- 落 `triumph_prefs.diagnosticLength`，沿用已有的云端同步链路（`auth.js` 的 `STATE_KEYS` 已登记 `prefs`），换设备能带过去。
- 诊断页按 `n/4` 每科抽题，四科才均衡。
- 档位**只允许 4 的倍数**：填任意值会让某些科目多抽，"最弱一环"就失去可比性，所以设置项故意做成固定档位而不是自由输入。
- 首屏文案也跟着变了：导航条、大标题（"**Twelve** questions. Eight minutes."）、正文、meta 全部读同一个值。选 24 就是 "Twenty-four questions"。

### 5.6 新增的付费链路

| 端点 | 作用 |
|---|---|
| `POST /api/diagnostic/report` | 生成/取回报告，未获权益 402 |
| `GET /api/diagnostic/report/status` | 只查权益，不下发报告 |
| `POST /api/billing/report-checkout` | **免登录**创建 $9.99 一次性结账 |

**免登录购买怎么落地**：凭证挂在匿名 `visitor_id` 上（不是邮箱）。结账时把 `{ kind: 'report', visitor_id }` 塞进 Creem 的 `metadata`；webhook 的 `checkout.completed` 看到 `kind === 'report'` 就发 `report_credit:<visitor_id>`。

> ⚠️ **这个 `kind` 分叉是必须的。** 少了它，一笔 $9.99 的一次性结账会掉进订阅分支，**白送一个 Pro**。代码里专门留了注释。

凭证语义：一次购买 = 一份报告，**但同一份报告允许重复下载**（用户不该为重新打开再付一次钱；报告缓存 180 天）。

### 5.7 一个必须告诉你的诚实结论

**「前 6 题免费」是 UX 引导，不是安全边界。**

`site/questions.js` 是公开静态文件，里面题库 969 题**带 `answer` 和 `explain` 字段**，任何人 `curl https://learndiag.com/questions.js` 就能拿到全部答案。诊断必须把题发到浏览器，所以这没法避免。

- **受影响**：错题回顾的门控、AI 错题分析（`/api/ai/analyze` 只要求登录，不要求付费）。
- **不受影响**：**报告本身**。报告是服务端生成 + 401/402 门控的，雷达图、九维分数、AI 趋势叙述**在解锁前根本不离开服务器**，这条是真保护。

所以我的建议是：**报告当成真正的付费内容来卖，错题回顾当成"再推一把"的引导**。如果想加密题库，那是另一个量级的工程（题面服务端渲染），而且会牺牲诊断的响应速度——不建议现在做。

## 十、门控实证（本轮自测证据，非纸面承诺）

「未解锁绝对不能渲染」是这一轮的硬要求，所以我没有只靠"代码看起来对"交付，而是搭了一次性探针直接调 `hDiagnosticReport`，把响应体全文打出来看。结论如下（探针跑完即删，未进 CI；等价的断言已固化在 `test/diagnostic-report.test.mjs` 的 15 项里）。

**探针 1：游客直接 POST 报告接口**

```
HTTP 状态 : 402
响应体全文 :
{"error":{"code":"report_locked",
          "message":"The full diagnostic report is not unlocked for this visitor yet.",
          "hint":"Log in for the free tier, or buy the one-time report — no account needed."},
 "status":402,
 "options":["login","purchase"],
 "free_review_limit":6,
 "tier":"free"}
```

逐项判定：

| # | 断言 | 结果 |
|---|---|---|
| 1 | 返回 402 而非 200 | PASS |
| 2 | `error.code = report_locked` | PASS |
| 3 | 免费回顾额度 = 6 | PASS |
| 4 | 报告字段零泄漏（递归扫 `radar`/`narrative`/`knowledge_points`/`miss_topics`/`misses`/`subtests`/`summary`/`pace`/`accuracy` 全无命中） | PASS |
| 5 | 响应体字符串里搜不到 `narrative` | PASS |
| 6 | 凭证未被偷偷消耗（KV 无 `report_credit:` 写入） | PASS |
| 7 | 报告未被写入缓存（KV 无 `report_cache:` 写入） | PASS |

**关键点**：402 分支在 `loadBank()` **之前**返回，也就是未解锁时服务端连题库都没查、报告对象的代码路径根本没执行过。这比"算完了再挑着不返回"强一个量级——不存在漏字段的可能。

**探针 2：伪造客户端判分**

给同一 visitor 注入一份 `report_credit` 让门控放行，然后提交一份**谎报结果**的答卷（第 1 题真做对但谎报 `correct:false`，第 2 题真做错但谎报 `correct:true`）：

```
解锁后 HTTP 状态 : 200
服务端判分       : 1/3 正确     ← 按题库重算，不是按客户端说辞
```

| # | 断言 | 结果 |
|---|---|---|
| 8 | 谎报 `correct:false` 不生效（做对的题没被算进错题） | PASS |
| 9 | 谎报 `correct:true` 不生效（做错的题被正确算进错题） | PASS |
| 10 | 服务端重算题数 = 提交题数 | PASS |

附带确认：`radar` 返回 **9 个维度**（与 `DIMENSIONS` 一致）；未配 `OPENROUTER_API_KEY` 时 `narrative` 走确定性兜底而非报错——**AI 挂了报告也不会白屏**。

## 十一、测试套件状态

**148 项，全部通过。**

上一轮遗留的 2 项红灯（`developers.html` 的 `<html lang="en">` 断言、5004 指南的 rel 链）已定位并修掉，**根因不是业务代码**：

- ardot 标注流程会给页面上**每一个标签**注入 `data-page-node-id="..."`，例如
  `<link rel="prev" href="..." data-page-node-id="81FjVuwv3YYgAYHYuKDPpP">`。
- 而这两个断言写的是**精确字符串相等**（`html.includes('<link rel="prev" href="...">')`、`assert.match(html, /<html lang="en">/`），多一个属性就匹配不上。

修法是让断言容忍标签内的额外属性（改用正则 + 转义），而不是去改页面或在标注流程里开口子。这样以后再跑标注也不会把测试打红，真实回归反而不会被这 2 项噪音盖住。
